# 迷宮ギミック仕様書

迷宮のギミック（仕掛け）の仕様。マップの定義は `public/data/maps/*.json`、オブジェクトの定義は `public/data/objects.json`。

この文書は仕様であり、実装の根拠として扱う。変更する場合は必ずユーザーの承認を得ること。

- **確定**: ユーザーが承認した仕様。
- **未決**: これから決める内容。

## 1. 現状（実装済みのギミック）

- 扉（`dungeon_door` など）、床の感圧板と連動する壁の矢罠（`wall_dart_trap`）、電気バリア（`electric_barrier`）、炎の噴出（`fire_jet_trap`）、回転ノコギリ（`rail_buzzsaw`）、スパイク・落とし穴などの罠がある。
- 「触れて操作する」スイッチやボタンは、感圧板（矢罠と連動）以外はない。

## 2. 時間制限ボタン（アイデア）【未決】

### 2-1. 概要

- プレイヤーが触れると、数秒だけ扉やバリアが開き、時間が来ると閉じるボタンギミックを、迷宮に追加する。
- 目的は、**迷宮の難易度調整**。

### 2-2. 難易度を動かすつまみ

- **ボタンから扉までの距離**: 長いほど、時間内に通れなくなる。
- **間の罠や敵**: 数や種類で、通り抜けにかかる時間と被るダメージが変わる。
- **開いている秒数**: 短いほど、速く走り抜ける必要がある。
- **戻り道**: 失敗したときに、ボタンへ戻る距離で、やり直しの重さが変わる。

例（イメージ）:
- 易しい: ボタンのすぐ近くに扉があり、開いている時間が長い。罠も少ない。
- 難しい: 罠の通路を抜けてから扉に着く。開いている時間は、ぎりぎりの長さ。

## 3. 未決の仕様

1. **ボタンの操作**: 近づいて決定キーを押すのか、触れただけで反応するのか。
2. **対象**: ボタン1個につき1つの扉か、複数の扉・バリアをまとめて動かせるか（マップの定義で、ボタンと対象を ID でつなぐ形が自然）。
3. **開いている時間**: 秒数を、ボタンごとにマップ側で指定するか。
4. **閉まる前の合図**: 閉まる直前に、点滅や効果音で知らせるか。
5. **挟まれたとき**: 閉まる扉・バリアの上にプレイヤーや敵がいたら、どうするか（押し出す、ダメージ、閉まらない）。
6. **再び押せるか**: 開いている間に押し直すと、時間が延びるか。
7. **敵の扱い**: 敵は閉じた扉を通れるか。

## 4. 罠のアイデア（メモ）【未決】

メモだけ。実装・仕様化は、決めてから。

- **吹き飛ばされる罠**: 罠に当たると、ダメージを受けるだけでなく、吹き飛ばされる（罠から抜けられるが、位置が変わる）。
  - 吹き飛ばす向き・距離によって、難易度を調整できる（通路の奥へ戻される、落とし穴に落ちる向きに飛ばされる、など）。
- **意地悪な落とし穴**: 歩いていると、ほぼ確実に落ちる配置・仕組みの落とし穴（回避の方法が分かりにくい、避けられない、など）。
  - 「確実に落ちる」の程度（絶対に落ちるのか、見抜けば避けられるのか）は未決。
- 上記は、時間制限ボタン（2章）と組み合わせると、難易度の調整の幅が広がる。

## 5. 実装の前に

- 上の未決を決めてから、迷宮に試験用の配置を作り、開いている秒数・距離・罠の数で、難易度を調整する。
- 追加する項目やマップの定義の形は、仕様が決まってから、この文書に追記する。
