# マップ仕様書

マップの大きさと、マップ同士のつなぎ方の仕様。マップの定義は `public/data/maps/*.json`。

この文書は仕様であり、実装の根拠として扱う。変更する場合は必ずユーザーの承認を得ること。

- **確定**: ユーザーが承認した仕様。
- **未決**: これから決める内容。

## 1. マップの大きさ【確定】

- 1つのマップの最大は、**100×100 マス**とする。
- 100×100 は上限で、負荷が大きいときは、上限を減らす（上限を下げて、マップを分ける）。
- 広い世界は、1つの巨大なマップにせず、複数のマップを、通路や門などでつないで表す。
- つなぎ方の例: 村から村長の家（建物の出入り）、マップの先の通路、門での移動。マップ間の移動は、すでにある `links`（扉・門・ポータル、`nextMap` と戻る先 `back`）の仕組みを使う。

## 2. 100×100 にした理由（測定結果）

3D 描画（three.js）は、画面に見えるものだけを描く（視錐台カリング）が、マップ全体の物を、1マス1メッシュで、最初に全部作る現在の作りでは、マス数に比例して、CPU の負担が増える。ヘッドレスの Chrome（ソフトウェア描画）で、N×N のダミーマップを測った結果（2026-10-29）:

| マップ | マス数 | 生成時間 | オブジェクト数 | 描画のCPU時間/フレーム | JSメモリ |
|---|---|---|---|---|---|
| 16×16 | 256 | 13ms | 498 | 2.6ms | 2MB |
| 48×48 | 2,304 | 53ms | 3,914 | 2.6ms | 8MB |
| 100×100 | 10,000 | 234ms | 16,002 | 9ms | 35MB |
| 200×200 | 40,000 | 0.8秒 | 62,720 | 34ms | 128MB |
| 300×300 | 90,000 | 1.9秒 | 140,930 | 78ms | 291MB |
| 500×500 | 250,000 | 4.6秒 | 389,266 | 228ms | 782MB |
| 1000×1000 | 1,000,000 | 22.5秒 | 1,548,330 | 867ms | 3,058MB |

- 60fps（約16ms/フレーム）を保てるのは、100×100 前後まで。
- 描画の呼び出し（draw call）は、どのサイズでも63回で、カリングは効いている。遅くなる原因は、見えない物の判定と行列の更新に使う CPU。
- 測定の限界: GPU の性能は測れていない（ソフトウェア描画）。プレイヤーを隅に置いた状態で、地形だけ（敵・NPCなし）。

## 3. 今後の改善（任意）

100×100 の上限の中でも、次の改善で、余裕を持たせられる。必要になったら、進める。

- 床を、1マスごとのメッシュから、1枚の大きな板（テクスチャの繰り返し）にする（オブジェクト数が、約半分になる見込み）。
- 動かない物は、`matrixAutoUpdate = false` にする。
- 壁・岩・木などを、`InstancedMesh` でまとめる。
- 100×100 を超える大きさは、チャンク（区画ごとの生成と破棄）が必要になる。上限が 100×100 なので、今は、対象外。

## 4. 未決

- 100×100 のマップに、敵・NPC・オブジェクトを置いたときの、実測（今回は、地形だけを測定）。

## 5. ブラウザでの確認結果【確定】

- 64×64 の街（`city.json`）を、ブラウザで確認し、問題なく動いた。
- 100×100 は広く、最大として十分。これ以上広げる必要はない。
- マップ間の移動（エリア移動）は、今の作りで違和感なく対応できる。ロード表示などの追加は、今は不要。
- 広さの目安: 64×64 の街でも、歩くと相当広く感じた。街のように建物や NPC が多い、密度の高いマップは、64×64 前後で十分。
- 草原のような、1つのエリアで見渡す広さが欲しいマップは、広いほうがよいので、上限は 100×100 のままにする（上限は下げない）。
- 上限（100×100）は、`test/links.test.mjs` の `MAP_MAX_SIZE` で、機械的にチェックしている。

## 6. 階段と、扉でのマップ移動【草案】

迷宮・建物の中の「階」の移動は、階ごとに別のマップにして、階段か扉でつなぐ。1つのマップの中で高さを変える作りにはしない（今の描画は、1マップ1階層）。

### 6-1. 階段（`type: "stairs"`）

- オブジェクト（`objects.json`）: `stairs_stone_up` / `stairs_stone_down`（石、迷宮向け）、`stairs_wood_up` / `stairs_wood_down`（木、屋内向け。床と天井つき）。`direction` が `up`（上り）か `down`（下り）。
- 見た目: どちらも、同じ材質の段を5つ並べた3Dの形（枠や黒い壁はなし）。上りは、段が高くなっていく。下りは、床に穴を開けて、段が浅く（1段 0.25）下へ降りていく（段ごとに明暗を交互にする）。穴の左右と奥には、段と同じ材質の壁を付ける（壁がないと、浅い角度から見たとき、穴の奥の下から空の色が透けて見える）。奥（段が低い・深い側）が、`dir` の向き。
- 動作: 階段のマスに踏み込むと、`links`（`"列,行"`）の `nextMap` へ移動する。扉や門と同じ仕組み。
- 行き先での出現位置は、link の `spawn`（`{ x, z, angle }`）で、双方の階段に明示する。戻る先の記録（`back`・`$back`）は使わない。建物の出口の `$back` は、階段を行き来しても、入った場所へ戻る。
- 向き（上る・下りる方向）: link の `dir`（`n` / `e` / `s` / `w`）で指定。省略すると、通れる隣のマスが1つだけのとき、その反対側（行き止まりの壁のほう）。それ以外は北。
- 決まり: 全ての階段のマスに links があり、`spawn` は通れるマスで、移動のマス（階段・扉・門）ではない（すぐ戻ってしまうため）。行き先のマップに、こちらへ戻る階段がある。`test/links.test.mjs` で機械的にチェックしている。

```json
// village_chief_house.json（1階）                          // village_chief_house_2f.json（2階）
"10,1": { "nextMap": "village_chief_house_2f",             "10,1": { "nextMap": "village_chief_house",
          "message": "階段を上る（2階へ）", "dir": "n",                "message": "階段を下りる（1階へ）", "dir": "n",
          "spawn": { "x": 10, "z": 2, "angle": 3.14159 } }             "spawn": { "x": 10, "z": 2, "angle": 3.14159 } }
```

### 6-2. 扉でのマップ移動

- 扉（`dungeon_door`・`wooden_door` など、`type: "door"` の全て）は、links に `nextMap` を書くと、開いた扉の中へ入ったときに、そのマップへ移動する（迷宮の扉でも、建物の扉でも同じ）。
- 戻る先は、`back`（このマップの通れるマスの位置）を書く。行き先の出口は `nextMap: "$back"`。

### 6-3. 試作と未確認

- 試作として、村長の家に2階（`village_chief_house_2f`）を作り、階段でつないだ。不要なら、マップとその links を消してよい。
- 描画は、ソフトウェア描画の Chrome（`--use-angle=swiftshader --enable-unsafe-swiftshader`）で、画面を撮って確認できる。
- 階段を踏んだときの効果音は、ポータルと同じ。専用の効果音・暗転は、未決。

## 7. 神殿【草案】

街や村の「神殿」の建物と、その内部。神殿の内部は、神殿専用のマップ（洞窟や迷宮と同じ、マップ1つの単位）にする。

### 7-1. 神殿のマップ（`temple.json`）

- 大きさは 21×20、壁の高さは 6（普通の建物の 4 より高い、神聖な広間）。屋内（`hasCeiling`）。
- 大理石（白に近い象牙色）の壁・床・天井、金の帯と目地。大理石のテクスチャ（`marble〜`）は、白く見えるように、少し自ら光らせる（`makeLitMaterial`。街・村の外観でも、灰色にならない）。赤地に金の絨毯が、入口から祭壇まで通る。明るい白い照明（霧は遠くにだけ）。
- 奥に、祭壇の段（0.3、0.6）と、女神像。左右の壁と奥の壁に、ステンドグラス。左右に、金の柱頭の柱が並ぶ。
- 神官は3人。**下っ端（修道女 `priest_woman`、助祭 `priest_man`）は、話すだけ**（広間を歩き回る）。**司祭（`priest_senior`）は、女神像の前（像の南 2 マス）に立って動かず**、近づいて話しかけると（Eキー）取引メニューを開く（店の種類は `shops.json` の `temple`）。「聖職者系ならできる、ギルド的な特別なこと」の窓口も、この司祭（未決。7-4）。
- マップの `npcs` の項目に、`shopId`（店の種類）、`speed`・`wanderRadius`（NPC 定義の歩き回りを、このマップだけ上書き）を指定できる。
- 出口は、入口の大扉（`temple_exit`、3マス幅）。街へ戻る（`$back`）。

### 7-1b. 神殿の作り分け（3種類）

| | 大神殿（城のある街）| 街の神殿（城の無い街）| 村の神殿 |
|---|---|---|---|
| マップ | `temple`（1階）・`temple_2f`・`temple_3f`（枢機卿の間） | `temple_town` | `temple_village` |
| 大きさ | 21×20（各階。3階は 11×10）、壁の高さ 12（1階）| 11×10（大神殿の約半分）、壁の高さ 6 | 7×7（さらに約半分）、壁の高さ 5 |
| 階数 | 3階建て（大理石の階段 `stairs_marble_up/down`）| 1階 | 1階 |
| 像 | 特大（普通の2倍。`goddess_statue_large`）| 普通（`goddess_statue`）| 小（普通の半分。`goddess_statue_small`）|
| 像の前 | 司祭（`priest_senior`）。店 `temple` | 普通の神官（`priest_man`）が受付。店 `temple_town` | 女性の神官（`priest_woman`）。店 `temple_village` |
| 他の神官 | 2階に修道女・助祭（話すだけ）。3階に枢機卿（話すだけ。普段は、表に出ない。今後のイベント用）| 修道女・助祭（話すだけ）で、計3人 | なし（1人）|

- 広さは、「ぐらい」の指定のため、仮の値（村は、歩ける広さを残すため、半分の半分より少し広い）。
- 城の無い街は、小さな町のマップ（`town.json`、28×24。道具屋・神殿・民家2軒・噴水・南の出口）。神殿の扉は1枚（十字架は1つ）。出口のポータルは草原（`grassland`）へつながる。世界のつながりは未決のため、画面上部のシーン切替に「町」のボタンを足した。民家は外観のみ（中に入れない）。
- 店の品物は、暫定。大神殿は、蘇生の薬・毒消し・猛毒消し。街の神殿は、蘇生の薬・毒消し。村の神殿は、毒消しのみ。

### 7-2. 画像のオブジェクト（sdServer の「オブジェクト」の画像）

- `statue`（像）: 台座の上に、画像の板が、常にこちらを向いて立つ。後ろに、淡い光の輪（`glow`）。台座の高さ（`pedestalHeight`）、画像の高さ（`height`）、当たり判定の半径（`radius`）を持つ。
- `wall_image`（壁の画像）: 壁のブロックの、通れる隣のマスに向いた面に、画像を貼る。画像は、自ら光る材質（ガラス越しの光）。画像の高さ（`height`）と、床からの高さ（`bottom`）を持つ。
- 画像は `public/images/objects/`、`sdId` で sdServer の画像と対応させ、`scripts/sync_sd_images.py` で、更新を取り込み直せる（`aspect` が更新される）。
- 登録した画像: 女神像（`goddess_statue`）、ステンドグラス4種（`stained_glass_plain`・`angel`・`priestess`・`prophet`）。

## 8. 飾り（天井・壁）

- `hanging`（天井から吊るす飾り）: 箱形のパーツ（`parts`）の組み合わせ。`fromCeiling: true` で、パーツの y は、天井からの相対（下向きは負）。通り抜けられる。炎などは `basic: true`（自ら光る材質）。**周囲を照らす光源は付けない（見た目のみ）**。床・天井は、`floorTexture`・`ceilingTexture` で指定（絨毯の上は `chandelier_castle_rug`）。
- `wall_deco`（壁の飾り）: 壁のブロックの、通れる隣のマスに向いた面に、箱形のパーツを付ける。座標は、面の中心からの相対（x: 横、y: 床からの高さ、z: 壁から手前へ）。
- 登録: シャンデリア（`chandelier_castle`・`chandelier_castle_rug`）、壁の燭台（`wall_sconce`）、赤い旗（`wall_banner_red`、壁の高さ5用）。
- 王城（`castle`）: 広間の絨毯の上に、シャンデリア6基。壁に、燭台と旗。
- 神殿: 大神殿は、大シャンデリア（`chandelier_temple_large_rug`、1階の絨毯の上に3基）と、大きな旗（`wall_banner_temple_tall`）、壁の燭台（`wall_sconce_marble`）。2階・3階は、シャンデリア（`chandelier_temple_rug`）、旗（`wall_banner_temple`）、燭台。街の神殿は、吊り燭台（`hanging_candles_rug`）と壁の燭台。村の神殿は、壁の燭台（`wall_sconce`、レンガ用）のみ。
- 貴族の屋敷（`mansion`・`mansion_2f`、17×14、壁の高さ5、木の壁・板張りの床）: 絨毯の上に小シャンデリア（`chandelier_mansion_rug`）、壁に燭台（`wall_sconce_wood`）と、カーテンつきの窓（`wall_window_curtain`、窓の両側に赤いカーテン）。

## 13. 中世の建物の部屋の割り振り（参考）と、神殿・屋敷への反映

### 13-1. 検索で確かめたことと、反映の差

- 大広間（グレート・ホール）が中心。家族の個室は、広間の奥（上座）側。台所・食料庫（パントリー）・酒蔵（バターリー）などの奉仕の部屋は、広間の反対側の通路の先。台所は、火事を避けて、広間から離すこともある。家族の寝室・居間（ソーラー）は、上の階（階段）。**→ 反映済み**（1階は広間と奉仕の部屋、個室は2階以降）。
- 修道院は、回廊（クロイスター）が中心。食堂（レフェクトリー）は台所の近く（回廊の外）。寝室（ドミトリー）は上の階。聖具室は、聖堂から入れる位置。客室と医務室は、本館から離す。**→ 反映済み**（食堂と台所を隣に、寝室は2階、聖具室は聖堂から）。
- 検索で分かった、まだ入れていない物（候補。決まったら足す）: 屋敷の食料庫・酒蔵（今は厨房の食器棚と木箱で代用）、神殿の回廊、医務室、客室を本館から離す（今の巡礼者の寝室は、街の神殿の2階）。
- この検索を受けて、大神殿の1階に、食堂（`temple_refectory`、聖堂の東の扉、厨房の隣）を足した。

### 13-2. 大神殿のグレードアップ（村・街の神殿の構成を、大きくしたもの）

検索で確かめた、大きな教会・修道院の構成（Britannica の abbey、worldhistory.org の The Layout of a Medieval Abbey、timeref.com の Parts of a Medieval Cathedral、Durham World Heritage Site の communal buildings ほか）を、大神殿に反映した。

- 検索で分かったこと: 十字形の聖堂（身廊・翼廊・内陣）。地下納骨堂は、内陣の下。回廊が、共同生活の中心（屋根つきの回廊と、中の庭）。参事会室（会議室）は、回廊の東側の大きな1室。写本室・図書室、宝物庫は、回廊の東の棟（出典によって位置は違う）。医務室と客室（巡礼者の宿）は、本館から離す。施し所（貧しい人に、修道士の食事の残りを配る）。寝室（ドミトリー）は、上の階。

### 18-1. 壁際の設備を、壁と隣にぴったり付ける

- かまど・オーブン・流し台・暖炉・食器棚は、本体の幅をマスいっぱい（4）にして、背中を壁（マスの端）にぴったり付けた。隣のマスの設備と、すき間なく、1本の台所の壁に見える。
- **家具の向きを、隣の壁に自動で合わせる**（`game.js` の furniture）: 壁に寄せた家具（`colliderOffset` の奥行きが 0.5 より大きい物）は、定義の向き（offset の符号の側が背中）の側に壁があればそのまま、なければ、北・南・西・東の順で、壁のある側に、背中を向ける。当たり判定も一緒に回す（東西の壁なら、幅と奥行きを入れ替え）。自動で回したくない物は、objects.json に `"autoTurn": false`。
- 直った不具合: 食器棚は、南の壁向きの作りで、北の壁に置くと壁から浮いていた。本棚・武器の棚・暖炉も、壁と反対の側に置かれた所があった（全部で約100か所）。

## 24. 外のマップの世界（端の移動）

- **世界の並び**: `public/data/world.json` の `grid`（マップ ID の 2 次元配列。上の行が北、右の列が東）。隣のマップは、配列の位置から決まる。マップごとに行き先は書かない。空き（`null`）は、隣なし。
- **大きさの固定**: 世界の並びに入れる外のマップは、すべて 64×64 マス（`mapSize`）。端を越えたとき、反対側の端の同じ位置に出るため。同じマップを、配列の 2 か所に置かない。
- **端の移動**: 隣があるほうの端の外へ出ると、隣のマップへ切り替わる（出現位置は、反対側の端の同じ位置。向きも引き継ぐ）。戻り先（`back`）は積まない。扉・階段・ゲートの移動とは別の扱い。
- **端の外の見た目**: 隣があるほうの端の外は、隣のマップの地面（`environment.floorType`）が、遠くまで続いて見える。切り替わっても、足元の地面は変わらない。隣がないほうの端の外は、何も描かない（空だけ）。
- **空・霧・光**: 端の移動のあと、3 秒かけて、新しいマップの色に変わる。

- **実装**: `public/js/world.js`（隣・端越え・位置の収め方）、`game.js`（端の外の地面、切り替え、色の切り替え）。

## 25. 起伏（高低差）

実装済み:
- マップの JSON に `heights`（行ごとの文字列。1 マス 1 文字の「段」。`0`〜`9`・`a`〜`z`、省略は 0）と `heightStep`（1 段の高さ。省略は 1.0）を書くと、地面に高低差がつく。`fallDamagePerLevel`（落下 1 段あたりのダメージ。省略は 8）も指定できる。
- 描画: 高いマスは、上面と、低い隣との境の側面を作る。段差 1 の側面は、地面と同じ模様。**段差 2 以上は崖**（岩肌。`cliffTexture`、省略は `cliffGray`）。
- 高いマスに置いた、木・草・壁・家具などは、そのマスの高さに乗る。敵と NPC も、立っている地面の高さに立つ。目線も、地面の高さに追従する（なめらか）。
- 歩き方: **1 段までの段差は、歩いて上れる**。2 段以上高い所へは、上れない（崖）。降りるのは、1 段は普通に、**2 段は飛び降りて降りられ**、`(降りた段数 − 1) × fallDamagePerLevel` のダメージ（2 段で 8）。**3 段以上の高さからは、降りられない**（崖の縁で止まる。ダメージも落下もない）。HP が 0 なら、マップを読み込み直す。
- 隣のマップへ続く端は、高さ 0（隣とずれない）。テストで確認する。
- 適用したマップ:
  - 山道（段 1.0、最大 9 段）: 川の谷、狭い道、崖。スポーンから、橋・東の端・南の端へ、崖を通らずに行ける道がある。
  - 砂漠（段 0.5、最大 5 段）: 斜めに走る砂丘。隣り合うマスの段差は 1 まで。
  - 極寒（段 0.6、最大 4 段）: なだらかな雪原の起伏。隣り合うマスの段差は 1 まで。

### 25-1. 弾の高さと、落ちても詰まないこと

実装済み:
- 起伏のあるマップでは、プレイヤーの弾（魔法・矢）は、**今いる地面の高さ（+1.3）から発射**する。正面の ±25 度・距離 40 以内の最も近い敵がいれば、**その敵の胴の高さへ、上下にも狙いをつける**（高い所から低い所の敵へ撃ち下ろす。低い所から高い所の敵へ撃ち上げる）。敵がいなければ水平に飛ぶ。
- 弾が敵に当たるのは、高さも合っているとき（敵の胴の高さ ±1.6）だけ。弾は、地面（崖の面・斜面）にぶつかると消える。
- 敵の弾も、敵が立っている地面の高さから出る。崖の下から撃った弾は、崖の面で消える。
- **落ちても詰まない**: 山道・砂漠・極寒は、歩けるマスが、段差 1 までの道で、すべて 1 つにつながる（崖から降りても、歩いて元の場所へ戻れる）。テストで確認する。

- **地上の敵は、地形に従う**: 崖（上り 2 段以上・下り 3 段以上）、毒沼・溶岩へは進まない。

## 32. ピラミッド（砂漠）

## 33. 敵の個性（厄介さ）と、プレイヤーの状態異常

調べたこと（ウェブ。敵の役割・対処の仕方の考え方）:
- 敵は、**役割（群れ・召喚・盾持ち・支援・自爆など）がはっきり分かり**、**プレイヤーが、考えて、対処する**（対策の道具・回り込み・優先順位）ことが、楽しさになる。
- 厄介なだけの（対処できない）敵は、不満になる。必ず、**対処の方法（予兆・よけ方・弱点）**を残す。

Sources:
- [Beyond Bullet Sponges: Designing Engaging Enemy Archetypes](https://www.wayline.io/blog/designing-engaging-enemy-archetypes)
- [Making enemies that are engaging and fun to fight](https://akela-morse.itch.io/seed-of-life/devlog/303588/making-enemies-that-are-engaging-and-fun-to-fight)
- [Designing Enemies With Distinct Functions](https://www.gamedeveloper.com/design/designing-enemies-with-distinct-functions)
- [WHAT ARE SOME ARCHETYPES FOR NON-BOSS ENEMIES?](https://rpgmaker.net/forums/topics/26056)
- [Spiteful AI（TV Tropes）](https://www.tvtropes.org/pmwiki/pmwiki.php/Main/SpitefulAI)

実装済み（敵の `abilities` から自動で決まる。`enemies.json` で個別に上書きもできる）:

| 個性 | 対象（能力・名前） | 動き | 対処 |
|---|---|---|---|
| **状態異常** | 毒・猛毒 / 火傷 / 麻痺 / 沈黙 / 鈍足 / 呪い | 攻撃が当たると、確率で、プレイヤーを状態異常にする。毒・火傷は、0.5 秒ごとの継続ダメージ。麻痺は、約 1 秒、動けず魔法も使えない。沈黙は、5 秒、呪文が使えない（弓は使える）。鈍足は、速さ 0.55 倍。呪いは、攻撃力 0.7 倍 | 時間で治る。場面が変わっても治る。画面（STATUS）に、状態と残り秒数が出る |
| **生命力吸収** | `lifesteal` | 与えたダメージの 35% を、自分が回復する | 短期決戦 |

## 38. ガーゴイル（固定砲台）と、魔法が効かない敵（2026-11-05。数値は暫定）

「うざい」敵。動かず、火の玉を連射し、複数いると鬱陶しい。高い所から撃ってくる。倒せるが、魔法（無属性以外）は効かない。

- **体力など**: HP 70・経験値 60（暫定）。近づけば、近接でも殴れる（触れると接触ダメージ）。

  - 魔法の属性は、`items.json` の呪文の `element`（fire / ice / none）。属性のない呪文は、無属性として扱う。

不具合の修正: 高台の宝箱が床に埋まる・高いマスの溶岩が地面の下に隠れて、見えないのにダメージを受ける。

- **持ち上げ**: 高低差のあるマスに置く物体は、そのマスの高さまで持ち上がる（`game.js` の `LIFT_TYPES`、または定義の `lift: true`）。**宝箱（`chest`）とポータル（`portal`）を、対象に加えた**（山道の塔・王城の中庭・神殿の回廊・洞窟・地下迷宮の宝箱が、床に埋まっていた）。
- **宝箱を開ける高さ**: 宝箱は、置かれている床の高さ（`floorY`）を持ち、プレイヤーが同じ床（段差 1 段まで）にいるときだけ、開けられる・開ける表示が出る（崖の下から、高台の宝箱を開けない）。`sameFloorAs`。
- **液体は、高さ 0 のマスだけ**: 溶岩・水・急流など（`liquid_tile`）は、高いマスにあると、地面の下に隠れる。
  - 火山の溶岩のうち、高さ 2 だった 22 マス（行 20）を、高さ 0 にした（湖の岸が、段差の崖になった）。
  - 山道の急流のうち、高いマスにあった 10 マスは、地面（通れるマス）に置き換えた（高さはそのまま）。
- **テスト**: 全マップで、高いマスの物体が持ち上げの対象であること、液体が高さ 0 のマスだけであること、宝箱が同じ床からだけ開けられることを検査する（`test/world.test.mjs`）。
- 確認: 地下迷宮の高台の宝箱が、台の上に乗る（実機の画面）。塔・洞窟の宝箱の高さは、床の高さと一致（数値）。火山の溶岩が、岸の崖から始まり、岸の上で、ダメージを受けない。

### 42-2. 吊橋の修正（手すりの位置・橋の下の通行。2026-11-05）

- **手すり**: 橋の脇（隣が、橋の床より 2 段以上低い谷）の縁だけに立てる。橋の端（同じ高さの地面とつながる側）は、出入り口なので、塞がない（以前は、四方を囲んでいた）。
- **橋の下を通れる**: 橋のマスは、**層が 2 つ**（橋の上＝`heights` の値・橋の下＝`bridgeUnder`）。動く者（プレイヤー・敵・村人・弾）は、今の高さに近い層（真ん中より上なら橋の上）を使う（`heightLevelAt(x, z, ref)`・`bridgeLayerLevel`）。谷の底からは、橋の下を南北に通れる。橋の上と下は、行き来できない（脇は崖）。
- **弾**: 橋の上の弾は、橋の床に当たって消える（上から）。橋の下から上へ撃った弾も、橋の床の厚みに当たって消える。橋の下を水平に飛ぶ弾は、通る。
- 確認: 谷の底を、橋の下の 8 マスを含めて、南から北へ通り抜けた（段 3 のまま）。橋の上を、西から東へ渡った（段 7 のまま）。画面で、橋の端に手すりがないこと・橋の下から橋の床が見えることを確認した。

### 43-1. 構成

### 43-2. 地形（画像から読み取る）

- **海**: 物体 `sea`（種類 `sea_tile`）。1 マスずつは描かず、マップの外まで広がる水面 1 枚と、並びごとの当たり判定にした（大量の水のマスで重くならない）。入れない・弾は通る。海岸の 1 マスは浅瀬（`water_shallow`）。湖の中央も `sea`、ふちは通常の水。

  - **マップの外の高さは、近い端のマスの高さ**（`heightLevelAt`・`heightLevelAtTile`）。以前は 0 としていたため、端の高さが 3 段以上の所で、「降りられない崖」と判定され、端で止まっていた（連続した高さの世界で、新しく出た不具合。端が 3 段以上の境は、約 3000 マスある）。
  - **マップ間の移動で、落下ダメージを受けない**: 読み込み中も、ゲームの時間は進み、新しい地形の高さが先に入る。プレイヤーが古い位置のまま動くと、段差を落下と判定していた。読み込み中（`nav.busy`）は、`movePlayer` が動かず、`applyHeightFall` もダメージなし。実機で、走って 6 か所の境を越えて、落下ダメージ 0 を確認した。
  - 斜面の段差 1 の側面は、上の面と同じ明るさ（マップの `sideShade: 1.0`。省略は 0.78）。段が、線に見えにくい。
- 歩ける: 出発点から、歩ける陸の 97% 以上へ、段差 1 までの道で行ける（川は、浅瀬で渡れる）。テストで確認（実測は約 99%）。
- 読み込み: 1 マップ平均 約 0.17 秒、最大 約 0.6 秒（実機、全 174 枚を測定）。

### 43-11. 大森林は、天然の迷宮（2026-11-05。暫定）
構想: 森林・樹海は、巨大な木々で視界が悪く真っ暗。同じような木々の間を進み、起伏があって、迷う。敵（虫・ヒルなど、湿地の嫌な敵）は、**今は出さない**（あとで決める）。
- **迷路**（`gen_world.py` の `build_maze`）: 3×3 マスを 1 区画とし、奇数番目の区画が部屋（通路）、その間が壁か通路。壁は、**巨木（3 倍）**の列（中心の行・列は、すき間なしの木。そのほかは半分）。通路は、**幅 3 マス**。全部の部屋が、深追い探索で、1 本の道でつながる（行き止まりと遠回り）。壁を 7% 抜いて、輪（ループ）を作る。森の外へは、25% が出入り口。
- 川・水のある所は、迷路にしない（そこは、木が少なめ＝12%）。川は、橋で渡る。
- **真っ暗**: 霧の近さ 5・遠さ 28、視界 0.4、環境光・空を暗い緑黒に（大湿原より、はるかに暗い）。実機で、数マス先は、巨木のシルエットだけ。
- **起伏が激しい**: 短い周期の丘と、尾根・谷（43-10。最大 約 25 段）。

### 43-27. 境界線のそばの川・出入り不可の空間（2026-11-06。「境界線近くの川を、渡れてしまう」「境界ギリギリの出入り不可の空間に入って、出られなくなる」の修正）
